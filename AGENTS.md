# Repository agent instructions

- Read `CONTRIBUTING.md`, `docs/skill-authoring.md`, and `docs/privacy-and-safety.md` before changing workflows.
- Inspect existing files and conventions before editing. Prefer focused changes over rewrites.
- Every skill must be a distinct task with a clear trigger, inputs, ordered workflow, output contract, example, edge cases and quality checks.
- Preserve the Agent Skills `SKILL.md` frontmatter convention: name equals folder; names are lowercase kebab-case; descriptions explain what and when.
- Keep skills focused and progressive-disclosure friendly. Link to supporting docs/templates instead of duplicating large reference material.
- Update the skill index, coverage map, examples, evaluation cases, validator and tests when adding or changing skills.
- Never invent statistics, benchmarks, platform features, user quotes, credentials, candidate facts or outcomes.
- Do not add LinkedIn scraping, browser automation, auto-posting, auto-messaging, auto-connection, auto-engagement or application-submission behavior.
- Protect personal, candidate, customer and employee data. Do not commit private user records, tokens, cookies, credentials or secrets.
- Hiring workflows must use observable job-related criteria, human review and privacy-aware data minimization. Never automate employment decisions or infer protected traits.
- Verify file links, skill metadata, tests and archive contents before claiming they pass.
